# 邻里闲置 · 产品需求文档（PRD）

版本：1.0 · 日期：2026-09-27 · 状态：开发基线，尚未实现。

本文件定义做什么、为谁做、如何验收；[SRS](../engineering/SRS.md) 定义系统如何满足这些要求。依据为用户提供的 AI Coding 实战考试题目。题目允许功能取舍，本文中的范围与交互为本项目的实施决策，并非题目逐字要求。

## 1. 产品目标与交付边界

做一个适配手机与电脑浏览器的社区闲置流转 Web 应用，在 24 小时开发窗口内交付可本地运行的前端、后端 API、持久化数据库，以及 5 分钟 Demo 视频、数据库 Chen E-R 图（全局联系图与实体属性图）、技术栈简介。

核心价值：让闲置及时被看见，让物品状态可信，让双方在应用内约定线下交接。

成功条件：两位邻居能分别用自己的会话完成“发布 → 想要 → 预约 → 确认 → 交接 → 归档”，刷新或重启服务后业务数据仍在；AI 发布辅助至少有一次真实 API 成功调用证据。

## 2. 用户与使用情境

| 用户 | 情境 | 要完成的事 |
| --- | --- | --- |
| 发布者 | 搬家、整理空间、孩子长大后物品闲置 | 快速发布，知道谁想要，选择领取人，确认交接完成 |
| 领取者 | 想在附近免费领取或购买物品 | 看清物品、价格、位置与可领取状态，表达意向并确认交接 |
| 访客 | 尚未选择演示身份 | 浏览、搜索、查看历史和社区数据 |

同一个用户可在不同物品下扮演不同角色。单一预置社区，展示昵称与楼栋，不收集手机号、精确住址或真实身份信息。

## 3. 范围与优先级

| ID | 优先级 | 需求 | 可观察的验收条件 |
| --- | --- | --- | --- |
| PRD-01 | P0 | 演示身份与权限 | 至少 3 个预置虚构邻居；不同浏览器会话可独立登录；未登录不可写入；不能操作他人物品 |
| PRD-02 | P0 | 发布物品 | 标题、描述、交易方式、标价（按需）、楼栋、预置图片可提交；发布成功立即可查；刷新后仍存在 |
| PRD-03 | P0 | 发现与检索 | 卡片按发布时间倒序；名称和描述关键词搜索；免费送、随便给、标价筛选可与搜索叠加；提供空态、加载态、错误重试 |
| PRD-04 | P0 | 表达想要 | 非发布者对可领取物品点“想要”；重复点击不重复计数；可撤回尚未进入预约的意向；发布者可查看有效意向名单 |
| PRD-05 | P0 | 预约与交接 | 发布者选一位意向用户并填写时间、公共地点；领取者确认或拒绝；预约取消后可重新选择；发布者在确认后标记完成 |
| PRD-06 | P0 | 归档与记录 | 送出后进入归档，保留描述、留言与完成记录；归档项只读；不可再次想要、留言、预约或重复成交 |
| PRD-07 | P0 | AI 发布辅助 | 调用真实 LLM API，根据标题和粗略描述返回可编辑文案、交易方式与参考价；用户主动采用；失败不阻断手工发布 |
| PRD-08 | P1 | 公开留言 | 已登录用户可对未归档物品留言、发布者可回复；按时间显示，所有人可读；不实现多层回复与私聊 |
| PRD-09 | P1 | 社区看板 | 展示本月发布、本月成交、当前在售、最快领走、最想要；均来自数据库，完成交易后可刷新看到变化 |
| PRD-10 | P0 | 考试交付 | 干净环境能按 README 启动；Chen E-R 图、技术栈简介、5 分钟视频与 AI Coding 使用记录齐备 |

P0 与 P1 均进入本次基线及验收；P1 在时间紧张时必须明确调整基线和关联任务后才可移出，不得静默跳过。

不纳入本次基线：多社区、真实注册与密码找回、信用积分、支付、快递、即时私聊、推送、图片上传、物品编辑删除、竞价、FAQ 自动回复、自动判断是否爽约。图片使用仓库内预置资源，选一张即可。

远端部署为可选加分项，不作为本地交付的前置条件；若启用，只使用虚构演示数据并限制外部访问与 AI 调用额度。

## 4. 页面与操作路径

| 路由 | 内容与主要动作 |
| --- | --- |
| `/` | 社区名、搜索框、交易方式筛选、可领取/已预约物品卡片、社区数据；“历史记录”入口 |
| `/items/:id` | 图片、描述、价格、楼栋、新鲜度、状态、留言；想要/撤回；发布者的意向名单与预约入口 |
| `/publish` | 标题、粗略描述、交易方式、价格、图片选择；AI 建议预览与采用；正式发布 |
| `/me` | 我发布的、我想要的、待确认/待交接预约；身份切换入口 |
| `/archive` | 已送出列表；只读详情 |

未登录操作引导选择演示身份，返回原页面；发布表单在当前标签页保留草稿。更换身份时清空旧身份缓存和草稿。预约信息只对交易双方可见，其他人只看到“已预约”。

### 主流程

1. A 选择演示身份，填写闲置电磁炉的信息，向 AI 请求建议。
2. A 查看并采用文案，自行确定标价后发布；首页立即出现该物品。
3. B 在独立会话搜索并留言，点击“想要”。
4. A 在意向名单选择 B，填写未来 7 天内的交接时间段与公共地点。
5. B 查看预约内容后确认，双方在“我的”页面看到待交接。
6. 线下交接完成后 A 点击“确认已送出”，二次确认后归档；看板成交数更新。

### 例外流程

- B 拒绝预约或任一方取消：物品恢复可领取，保留取消记录；原意向仍可用。
- 未确认或爽约：由任一方手动取消，没有自动过期或自动完成。
- A 想换领取者：先取消现有预约，再选择其他有效意向人。
- 多人同时操作：只有一个预约能成功，其余收到明确的“状态已变化，请刷新”。
- AI 超时、无凭据或额度不足：显示原因与重试入口，保留所有表单输入，不用假结果冒充成功。

## 5. 业务规则

### 5.1 交易方式与价格

- 免费送 `FREE`：价格为 0，卡片显示“免费送”。
- 随便给 `FLEXIBLE`：无固定价格，卡片显示“随便给”，不接受标价字段。
- 标价 `FIXED`：人民币大于 0，最多两位小数，上限 99,999 元。
- 价格不是在线支付或结算承诺；应用只协助线下交易。

### 5.2 新鲜度

以服务端时间与发布时间的差计算：小于 24 小时为“刚上架”；大于等于 24 且小于 72 小时为“新上架”；大于等于 72 小时为“已上架 X 天”，X 取经过小时数除以 24 向下取整。预约、留言和完成操作不刷新发布时间。

### 5.3 状态与权限

- 物品：可领取 `AVAILABLE` → 已预约 `RESERVED` → 已送出 `GIVEN`；取消预约从 `RESERVED` 回到 `AVAILABLE`。
- 预约：待确认 `PENDING` → 已确认 `CONFIRMED` → 已完成 `COMPLETED`；待确认或已确认可取消为 `CANCELLED`。
- 只有发布者能创建预约与确认送出；只有被选中的领取者能确认预约；交易双方均可取消未完成预约。
- 发布者不能想要自己的物品；已预约物品禁止新增/撤回意向，但仍可公开留言；已送出全面只读。
- 不支持绕过预约直接送出，以保证领取人和成交记录完整。

### 5.4 看板口径

- 本月：北京时间本月 1 日 00:00（含）至下月 1 日 00:00（不含）。
- 本月发布：按物品发布时间计数，包含后来已送出的物品。
- 本月成交：按交易完成时间计数，不计取消和预约。
- 当前在售：所有未送出物品，即 `AVAILABLE + RESERVED`；界面注释“含已预约”。
- 最快被领走：全部已完成交易中，完成时间减物品发布时间最短的一件；并列按完成时间、物品 ID 升序。
- 最想要：全部未送出物品中有效意向人数最多的一件；并列按发布时间倒序、物品 ID 倒序。无人想要时显示暂无。

## 6. 体验标准

- 390px 手机宽度和 1440px 桌面宽度均无横向溢出；卡片清楚展示图片、标题、价格、楼栋和状态。
- 主要按钮触控区域至少 44 × 44 CSS px；表单有可见标签与字段级错误；状态不能仅依赖颜色表达。
- 搜索保留当前筛选；操作进行中禁用重复提交，成功或失败均有清晰反馈。
- 正文使用纯文本渲染；归档页保留阅读价值但不出现可写操作入口。
- 页面以生活物品为中心，避免做成管理后台；统一留白、字级与有限的状态颜色。

## 7. AI 能力的边界

只根据用户明确提供的信息整理文案，不补造品牌、成色、故障状况或购买年份。缺少信息时返回待补充问题。参考价明确提示“基于描述的 AI 建议，非市场行情估价”。模型结果必须通过服务端结构校验，发布必须由用户主动提交。

## 8. 验收与演示

验收用例详见 SRS 的测试矩阵。至少演示一条双会话完整交易、一条取消恢复、一条越权拒绝，以及一次真实 AI 调用。需分别记录本地测试结果、真实模型结果与可选部署结果。

视频建议：0:00–0:30 痛点与范围；0:30–1:30 AI 辅助发布；1:30–2:50 双角色想要、预约、确认与交接；2:50–3:30 归档与看板；3:30–4:20 架构、ER 图与并发约束；4:20–5:00 AI Coding 使用方式、测试结果与边界。

## 9. 已作决策与待具备条件

已作决策：单社区、移动端优先 Web、演示身份、预置图片、手动交接确认、真实 LLM 发布辅助、使用本地 SQLite。均为压缩到 24 小时的范围选择。

待具备条件：实现真实 LLM 验收时需要可用服务商、模型与服务端 API 凭据；不阻塞契约及其余功能开发，但阻塞真实 AI 验收与完整交付。凭据通过本地环境变量配置，不提交或写进 Issue。可选远端部署需届时确认托管资源。
